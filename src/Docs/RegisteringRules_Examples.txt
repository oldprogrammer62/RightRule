You can configure each rule with a specific "decision word" and "decision data" 
for both true and false outcomes.

Decision Word:
Tells the calling application which decision was made so it can route to the next logical step.
Recommended to use a switch statement to handle all possible decision words for the current 'context'. Should also include the 'NODECISION' result.

Decision Data: 
Returns additional, context-specific information that the calling application can use during downstream processing.



Initialise a Rule Definition and Register
-----------------------------------------
IRightRule rr = new RightRule.RightRule();

RuleDefinition rule = new()
{
    Number = 1,
    Name = "Rule1",
    Context = "Context",
    Statement = "Test.boolvalue equals true",
    TrueDecision = "EQUALS",
    TrueDecisionData = null,
    FalseDecision = "NOTEQUALS",
    FalseDecisionData = null,
    OptionalData = null
};
RuleRegistrationResult rule1 = rr.RegisterRule(rule);


Build a Rule Definition and Register
------------------------------------
IRightRule rr = new RightRule.RightRule();
RuleDefinition rule = rr.BuildRule()
   .Number(1)
   .Name("Rule1")
   .Context("Context")
   .Statement("Test.boolvalue equals true")
   .TrueDecision("EQUALS")
   .TrueDecisionData(null)
   .FalseDecision("NOTEQUALS")
   .FalseDecisionData(null)
   .OptionalData(null)
   .Build()
   .Register(rr.RuleService);
